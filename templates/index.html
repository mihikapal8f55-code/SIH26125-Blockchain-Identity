1

Biometric Liveness Challenge

1

2

3

Selective-Disclosure Claim Picker NEW

Issue a credential with many claims, then disclose only the ones a verifier needs - "prove you are 18+, not when you were born". The verifier only ever sees the sub-digest of the withheld claims.

Witness Co-Signing

A sensitive action (e.g. blueprint export) requires a second nearby identity to co-sign inside a time window. The forging is QR-paired: a wrong pairing code means no proximity.

Identity Lifecycle Cascade

Promotion/transfer is not a grant change - it is a cascade: the moment the identity moves, every stale grant auto-revokes and only the new role's clearances remain.

1
Dynamic smart-contract policy - not rigid RBAC

Delegation Chains

3

Travel-Mode Context Access

2

3

Rule Dry-Run Simulator

Evaluate ABAC + smart-contract rules BEFORE touching the chain

Duress PIN (Silent Alarms)

1
Enroll a panic PIN alongside the normal PIN
2
Entering the duress PIN LOOKS like a normal successful unlock
3

Two-Person Integrity at Access Time

1
Viewer A opens a window on a guarded resource (e.g. blueprint_export)
2
A SECOND distinct identity must co-authorize; neither can view alone
3
Only then is read access granted - under an audited dual-signature window

Risk-Adaptive Step-Up Auth

1
Anomaly engine scores the identity (velocity/teleport/honeytoken/duress)
2
low risk -> ZK proof; medium -> + biometric; high -> + two-person rule
3
The score decides the factors that the ABAC engine demands

Purpose Binding NEW

Right person + right purpose + right time: a valid-role request is DENIED when its purpose is not registered for that resource. Denials are audited on-chain.

Session Sealing & Mobility Defense

Sessions are cryptographically bound to device + IP for a lease. Move to another device/IP and the binding shatters - the "user" is forced to re-authenticate with a risk-score spike.

Data-Classification Rule Layers

Tag a resource with a classification label once; it inherits the layer's rules (required factors, minimum level, watermark) instantly - no per-resource controls to configure.

Node PKI (Signed Gossip)

G-Series Security  ·  Break-glass ledger · Adaptive JIT step-up · TOTP · Revocation list + ZK proofs · Honeytoken deception · Velocity/teleport · k-anonymity · measured-boot attestation · PII redaction · cross-org federation

G1 · Break-Glass Emergency Access

1
Open a JIT high-privilege window - audited on-chain with a unique emergency id and 10-minute expiry
2
A SECOND independent operator MUST approve first (two-person rule), otherwise the window stays unusable
3
Every open / approve / use is scored by the anomaly engine - the alert records WHO unlocked it

G2 · Adaptive (JIT) Step-Up Authentication

1
Every access attempt scores a live risk (trust, open anomalies, sensitivity) -> GRANTED / STEP_UP / DENIED
2
A STEP_UP verdict opens a just-in-time challenge - nothing is granted until the extra factor verifies
3
Successful proof mints a time-boxed JIT grant, anchored on-chain as a JIT-STEPUP-GRANT block

G3 · TOTP Second Factor (RFC 6238)

1
Enroll generates a fresh base32 secret + otpauth URI, sealed into an on-chain TOTP-ENROLL record
2
Verification accepts a time-synchronized 6-digit code within a sliding window of ±2 steps
3
Reset revokes the seed on-chain - the old authenticator dies and the next code is unusable

G4 · Global Revocation List + ZK Status Proof

1
Revoked identities land on a release-safe CRL - only one-way commitments are published, never identifiers
2
Any relying party can ask REVOKED or NOT? via a ZK proof bound to a fresh single-use challenge
3
The identity is never disclosed to the verifier - only a freshly-derived proof token is

G5 · Honeytoken Deception Trap

1
Plant a decoy credential that LOOKS like a high-value secret - real code never touches it
2
ANY attempt to use a honeytoken is, by definition, an attacker - freeze a HIGH anomaly alert instantly
3
Every plant and every touch is anchored on-chain as HONEYTOKEN-PLANT / HONEYTOKEN-TOUCH blocks

G6 · Physical Velocity / Teleport Detection

1
Two check-in locations + elapsed time are reduced to a great-circle distance and a real km/h speed
2
Beyond the max speed ceiling the move is TELEPORT - a HIGH-severity anomaly alert auto-fires
3
Every move is anchored on-chain as a VELOCITY-CHECK block - even plausible ones

G7 · k-Anonymity Aggregate Reports

1
Export-safe statistics: clearance / role / department / zone / anomaly distributions
2
Any bucket with fewer than k records is suppressed (null) - cannot re-identify a single person
3
Individual identities appear only as irreversible peppered HMAC pseudonyms

G8 · PII Redaction / Right-to-Erasure

1
Erasure requests tombstone a specific identity field - only an irreversible value hash is stored
2
The audit trail records a PII_REDACTION entry with the hash, never the plaintext value
3
Prove, on demand, that a field's live value has been redacted - compliance & right-to-erasure

G9 · Measured-Boot Device Attestation

1
Anchor a device's golden measured-boot quote (TPM-style) - only its SHA-256 digest is stored
2
Logins ONLY succeed when the presented quote hashes to the golden value; tampered firmware is denied
3
Compromise response: revoke the device and its quote is refused chain-wide

G10 · Cross-Org Federation (Trust-Anchored)

1
Partner orgs' DID public keys are pinned on-chain as trust anchors in a federation registry
2
A verifier honours a cross-org credential ONLY if its issuer anchor is registered and TRUSTED
3
Negative control built in: the same predicate from an untrusted issuer is rejected outright
